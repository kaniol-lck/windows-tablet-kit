# TouchToMouse —— 触摸→鼠标的诊断与改写（鼠标钩子路线）

给"桌面能点、游戏里点不动"排查用的小工具，**不需要任何特权**（这也是它相对 `TouchRedirect` 的唯一优势）。

- **探针模式**（默认）：只挂一个全局低级鼠标钩子（`WH_MOUSE_LL`）观察每条鼠标消息的 `dwExtraInfo`，
  **不改动任何输入**。用来判定某个游戏属于哪一类问题：
  - 日志出现 `TOUCH L-DOWN/L-UP … extra=0xFF5157xx` → 该程序走鼠标消息通路（只是忽略触摸签名或不读鼠标消息）→ **转换模式能救**；
  - 一条 `TOUCH` 都没有（只有真实鼠标事件或空白）→ 程序自己处理了 `WM_POINTER*`，Windows 不再做提升，
    **根本没有鼠标消息可改** → 需要用 `TouchRedirect` 的全局重定向模式。
- **转换模式**：把带触摸签名的按键事件**吞掉**，再用 `SendInput` 重注入一条 `ExtraInfo=0` 的干净鼠标事件。
  对游戏来说就是一次真实鼠标输入，走 RawInput 的程序也能收到。
- **自检**：用内部注入的、带标记的"假触摸"事件验证"钩子看到几次 → 目标窗口就只能收到几次"
  （多 1 次＝没吞掉会双击，少 1 次＝重注入没送到）。

## 用法

1. `编译.cmd`（本机执行策略可能禁止直接跑 `.ps1`，所以编译走这个 `.cmd`）。
2. `1-探针模式.cmd` → 在目标游戏里用手指点几下 → 回窗口按 `Ctrl+C` 看统计与"判读"两行。
3. 如果判读是"走鼠标消息通路"，用 `2-转换模式.cmd`（名单从命令行或 `games.txt` 读）。
4. `3-自检.cmd` 随时可以验证转换通路本身是否正常。

命令行参数：

| 参数 | 说明 |
|---|---|
| `-convert` | 转换模式（默认是探针模式） |
| `-only a.exe b.exe` | 仅当前台进程名在这些名字里时改写；`xxx.exe` 会自动去掉后缀；支持空格/逗号/分号分隔 |
| `-add` | 不吞掉原事件，只额外补一条干净点击（默认是吞掉替换，避免双击） |
| `-log <路径>` | 指定日志文件 |
| `-seconds N` | N 秒后自动停止并打印统计 |
| `-selftest` | 自检 |
| `-injectmove` | 子进程模式：只注入两次位移后退出（被钩子自检调用） |

启动时还会打印环境诊断（窗口站 / 进程桌面 / 输入桌面 / 完整性级别）与两组"钩子自检"
（本进程注入、另一进程注入），用来先排除权限问题：**低完整性进程能装上全局钩子却收不到别的进程的输入**。

## ⚠️ 血泪教训：低级钩子回调里绝不能注入输入

初版在 `WH_MOUSE_LL` 回调里直接调 `SendInput`，第一次注入就**内核态死锁**：进程卡在"正在终止"、
任务管理器与 `taskkill`（含提权）都杀不掉、exe 被锁、连 `SendInput` 注入通路都被堵住，最后靠内核自行回收。

正确做法（本项目就是这么做）：**回调只做"判断 + 入队 + `return 1`（吞掉）"，真正的注入与日志交给 UI 定时器**。

## 说明

- 配置与日志：`games.txt`（转换模式名单，一行一个进程名，`;` 注释）、运行目录下的 `TouchToMouse.log`。
- 本工具与 `TouchRedirect` 重叠的功能是"转换模式"；`TouchRedirect` 一个程序就把两套机制都做了，日常用那个即可。
  这里保留的理由是**探针**：它不需要签名、不需要 UI Access，随时能用来判断"这个游戏到底属于哪一类"。
