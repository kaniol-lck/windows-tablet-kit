# TouchRedirect —— 把触摸变成真正的鼠标（含"按游戏自动选最省事方案"）

**解决的问题**：桌面能点、游戏里点不动。

程序内置两套机制，按**前台进程**自动选最省事的那套：

| 列表 | 机制 | 适用 | 代价 |
|---|---|---|---|
| `[convert]` | **改写触摸派生的鼠标消息**：吞掉带 `0xFF515700` 触摸签名的点击，用 `SendInput` 重注入一条干净的鼠标事件 | 游戏走鼠标消息通路，只是忽略触摸签名或不读鼠标消息（例：Stacklands） | 无 —— 不需要任何特权 |
| `[redirect]` | **全局触摸重定向**：拿到 **UI Access** 后用 `RegisterPointerInputTarget(PT_TOUCH)` 把整个桌面的触摸先收到自己窗口，再转成真实鼠标事件 | 引擎自己处理 `WM_POINTER*` 的程序（例：Unreal 引擎的游戏），Windows 因此不再做"触摸→鼠标"提升 | 需要签名 + 装到 Program Files（安装脚本已包办） |

**名单外的程序一律不插手**，触摸完全保持原生（双指缩放、长按右键都在）。名单为空时两套机制都不启用。

## 为什么必须"签名 + 装在 Program Files"

`RegisterPointerInputTarget` 的文档写明：调用线程必须有 **UI Access** 权限，否则返回 `ERROR_ACCESS_DENIED`。
UI Access 的三个硬条件：

1. 清单里 `requestedExecutionLevel level="asInvoker" uiAccess="true"`（本目录 `app.manifest` 已经这么写）；
2. exe 放在**安全目录**（`C:\Program Files\`）；
3. exe 由**受信任证书签名**。

**实测结论（2026-10）**：**自签证书**（装进本机「受信任的根」+「受信任的发布者」）+ Program Files 就够了，
不必买商业证书。探针（`RegisterPointerInputTarget` 成功 / `TokenUIAccess=1`）已验证。

> 别直接运行源码目录里编译出来的 exe：没签名/不在 Program Files 时 Windows 会拒绝启动，报
> `A referral was returned from the server` —— 这正说明清单生效了，必须走安装脚本。

## 安装 / 卸载

- 安装或升级：双击 `1-安装-需管理员.cmd`（会弹 UAC）。脚本会：备好 `CN=TouchRedirect Local Test` 自签证书 →
  装进本机受信任存储 → 用 `csc.exe` 编译并嵌入清单 → 签名 → 停掉旧实例 → 复制到 `C:\Program Files\TouchRedirect\` →
  重建开始菜单快捷方式 → 用 explorer 以**普通权限**启动（托盘运行）。
- 卸载：`2-卸载-需管理员.cmd`（程序目录 + 快捷方式 + 证书；名单与日志保留，要一起删给 `uninstall.ps1` 加 `-PurgeData`）。

## 配置

`%LOCALAPPDATA%\TouchRedirect\games.ini`（首次运行自动生成）：

```ini
; ---- 转换模式：改写触摸派生的鼠标消息（不需要特权，最省事）----
[convert]
stacklands

; ---- 重定向模式：全局触摸重定向（需要 UI Access）----
[redirect]
godsoul*

[options]
hidecursor=0
suppresscursor=1
```

- 一行一个进程名（写 `xxx.exe` 也行），支持 `*` 和 `?` 通配，`;` / `#` 开头是注释。
- 改完在托盘菜单点 **「重新加载配置」**即可生效，不必重启（改文件后程序也会自动重载）。
- 前台进程名看日志里的 `（前台=xxx）`，照抄进列表即可。

## 托盘菜单

状态（重定向生效 / 转换生效 / 空闲 / 暂停，含当前前台与计数）、暂停（触摸保持原生）、
重新加载配置、打开配置文件、打开日志、退出。

切换前台、暂停、退出、异常退出都会**注销重定向、还原被改过的目标进程状态、并补发一次左键抬起**，不会让鼠标键卡住。

## 两个光标相关选项

### `suppresscursor`（默认 1）

有些程序的指针是**硬件光标但用了它自己的图片**，替换系统光标表对它无效（实测 GodSoul 就是这样：
GDI 截图里不含指针 → 是硬件光标；但替换 17 种系统光标后它照旧显示 → 用的是自己的图片）。于是改为**拦掉它"设置光标"这个动作**：

1. `SetClassLongPtr(hwnd, GCLP_HCURSOR, NULL)`：把目标进程所有顶层窗口的**类光标置空**，**每 500 ms 复查一次**
   （程序在进入加载状态等情况会重新设置自己的类光标，一次性置空挡不住）；
2. **改写目标进程主模块导入表里 `user32!SetCursor` 那一项**，指向写在该进程内存里的 14 字节小桩：

   ```asm
   31 C9              xor ecx, ecx          ; hCursor = NULL
   48 B8 <真 SetCursor> mov rax, <真 SetCursor>
   FF E0              jmp rax               ; 尾调用，栈不动
   ```

   于是"程序设置自己的光标"变成"设置 NULL" → 不画任何指针。

改写前会**校验**该 IAT 项当前值确实落在目标进程的 `user32.dll` 模块地址范围内；两条都保留原值，
注销 / 暂停 / 退出都会原样还原。诊断开关 `-patchtest <pid>` 可以拿任意进程试一遍（随后自动还原）。

> ⚠️ 若本工具在"已改写"状态下被强杀，目标进程里的改写会保留到它重启为止（表现为那个程序里看不到指针）。
> 不想用这个功能就把 `suppresscursor` 设成 `0`。

### `hidecursor`（默认 0，一般不用开）

| 值 | 行为 |
|---|---|
| `0`（默认） | 不碰系统光标表 —— 靠 `suppresscursor` 就够了 |
| `1` | 在该游戏里一直隐藏系统光标 |
| `2` | 只在手指按住的那一下隐藏 |
| `3` | 按住时隐藏、松开约 2 秒后恢复 |

> ⚠️ 开启它的代价（实测）：本机 `SPI_SETCURSORS` 失效，隐藏后只能拿原始 `.cur` 文件逐个回写恢复；
> 而 Windows 是**在加载光标方案时**才应用"可访问性指针"的 **缩放与颜色**（如 `CursorSize`/`CursorColor`/`CursorBaseSize`），
> 所以回写出来的是**未缩放、未上色的原图** → 指针大小/观感会和设置不一致。
> 万一被弄乱：跑 `修复光标外观.cmd`，在「鼠标属性 → 指针」里点应用/确定（或把「指针大小」滑块动一格再动回来）。

## 行为与边界

- 重定向模式只用**主触点**（第一个落下的手指），其余手指忽略；名单内的程序里没有双指手势。
- 两种模式下光标都会被移到手指位置，所以需要"悬停"才响应的 UI（Unity/UE 常见）也能正常。
- **锁定/隐藏光标**的第一人称游戏（用相对位移瞄准）不适合触摸，本工具也帮不上。
- 带内核反作弊的联机游戏：注入的是真实鼠标输入，一般不会被判违规，但**自己权衡**，别在竞技网游上冒险。
- 目标程序若以管理员运行，本工具通常仍能驱动它（UIAccess 正是为跨权限辅助设计的）；拿不准就以管理员身份运行本工具。

## 排错

日志：`%LOCALAPPDATA%\TouchRedirect\TouchRedirect.log`（每次状态切换、每次触摸都会记一行）

| 日志内容 | 意思 |
|---|---|
| `TokenUIAccess = 0` | 没拿到 UI Access：签名无效 / 不在 Program Files / 清单被改坏 → 重跑安装脚本 |
| `重定向已注册（前台=xxx）` | 重定向生效中，此刻手指点击就是真实鼠标左键 |
| `重定向注册失败 err=5` | 权限不足，或被别的程序占着该桌面的触摸重定向 |
| `类光标已置空：… / IAT 已改写：user32!SetCursor …` | `suppresscursor` 生效，目标程序不再显示自己的指针 |
| 一直"空闲" | 前台进程名与名单不匹配 → 看日志里的 `（前台=）` 照抄进 `games.ini` |

## 诊断/实验脚本

| 脚本 | 用途 |
|---|---|
| `测试-隐藏光标10秒.cmd` | 把 17 种系统光标替换为空白并保持 10 秒后还原 —— 验证本机 `SetSystemCursor` 到底有没有视觉效果 |
| `测试-截图看光标.cmd` | 连拍 20 张截图（GDI 截图**不含硬件光标**）→ 判断某个指针是"画进画面的软件光标"还是"硬件光标用了自己的图片" |
| `紧急恢复鼠标指针.cmd` | 系统光标万一被留在隐藏状态时的一键恢复 |
| `修复光标外观.cmd` | 指针的缩放/颜色被弄乱后，让 Windows 重新加载光标方案 |

## 已知环境事实（实测，供参考）

- `SetSystemCursor(hcur, 0)` 的"替换全部系统光标"在 Windows 10 上返回失败（`err=203`）→ 只能逐个替换 `OCR_*`。
- `SystemParametersInfo(SPI_SETCURSORS)` 在部分精简/定制系统上返回 `False`（"重新加载光标方案"这条路不通）。
- 触摸派生的鼠标消息带签名 `GetMessageExtraInfo() & 0xFFFFFF00 == 0xFF515700`（`& 0x80` 位 1=触摸、0=笔）。
